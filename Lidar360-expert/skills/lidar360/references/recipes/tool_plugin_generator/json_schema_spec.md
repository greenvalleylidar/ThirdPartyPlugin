# JSON Schema Interface Specification

## Overall Structure

JSON Schema is used to define interface metadata and parameter specifications, consisting of three core parts:

```json
{
  "interface": { ... },    // Interface metadata
  "input_schema": { ... }, // Input parameter definitions
  "output_schema": { ... } // Output result definitions
}
```

### Core Rules

1. Names must not duplicate those used by other algorithms
2. Nested object `title` values must not duplicate other titles

---

## Interface Metadata

```json
{
  "name": "pointcloud_outlier_removal",           // Unique interface identifier (lowercase snake_case)
  "title": "Point Cloud Denoising",               // Interface display name
  "description": "Remove noise points while...",   // Function description
  "version": "1.0.0",                             // Interface version number (current wizard default)
  "category": "pointcloud_processing",            // Function category (lowercase snake_case)
  "keywords": ["PointCloud", "removal noise"]     // Search keywords
}
```

### Field Descriptions

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| name | string | Yes | Unique interface identifier, lowercase snake_case |
| title | string | Yes | Display name |
| description | string | Yes | Function description |
| version | string | Yes | Valid version string; current wizard defaults to `1.0.0` |
| category | string | No | Not directly generated by current wizard UI; when provided manually, use lowercase snake_case |
| keywords | array | No | Search keyword list |

---

## Input Schema

```json
{
  "type": "object",
  "description": "Point cloud denoising parameters",
  "properties": {                          // Parameter list
    "neighbor_points": {
      "type": "integer",                   // Parameter type
      "title": "Neighborhood Points",       // Parameter title
      "description": "number of...",       // Parameter description
      "default": 10,                       // Default value
      "example": 10                        // Example value
    }
  },
  "required": [],                         // Required parameter list
  "input_data": { ... },                  // Input file parameter specification
  "output_data": { ... }                  // Output file parameter specification
}
```

### Properties Parameter Fields

Each parameter may contain the following attributes:

| Attribute | Type | Description |
|-----------|------|-------------|
| type | string | Parameter type: integer, number, string, boolean |
| description | string | Description |
| default | any | Default value (non-required parameters must provide one) |
| example | any | Example value |
| minimum | number | Minimum value constraint |
| maximum | number | Maximum value constraint |
| enum | array | Enum value list |

### File Data Handling Specifications

#### Data Field Naming Rules

In `input_schema` and `output_schema`, the JSON keys for data fields follow these rules:

- **The key for input fields must be `input_data`**, whether there is one or multiple inputs
- **The key for output fields must be `output_data`**, whether there is one or multiple outputs
- **For single input/output**, the value is a single object
- **For multiple inputs/outputs**, the value is an array, with each element distinguishable by the `name` field
- **Each data field must include a `title` field** for UI display, usually with "Input"/"Output" prefixes

```json
// Single input
"input_data": { "type": "file", "name": "input_data", "title": "Input Point Cloud File", ... }

// Multiple inputs -- key is still input_data, value is an array
"input_data": [
    { "type": "file", "name": "input_data", "title": "Input Point Cloud File", ... },
    { "type": "file", "name": "input_dem", "title": "Input DEM", ... }
]

// Single output
"output_data": { "type": "file", "name": "output_data", "title": "Output Point Cloud File", ... }

// Multiple outputs -- key is still output_data, value is an array
"output_data": [
    { "type": "file", "name": "output_file", "title": "Output Result File", ... },
    { "type": "file", "name": "report_file", "title": "Output Report File", ... }
]
```

#### 1. Single File Input (type: "file")

```json
{
  "type": "file",
  "name": "input_data",                   // Parameter name
  "title": "Input Point Cloud File",       // Title (with Input/Output prefix)
  "description": "Point cloud file path", // Description
  "suffix_name": ["lidata"],              // Supported lowercase suffixes
  "required": true                        // Whether required
}
```

#### 2. Multiple File Input (type: "multifile")

```json
{
  "type": "multifile",
  "name": "input_rasters",
  "title": "Input Raster File List",
  "description": "Input raster file list",
  "suffix_name": ["jpg", "png"]
}
```

#### 3. Directory Input (type: "dir")

```json
{
  "type": "dir",
  "name": "input_dir",
  "title": "Input Directory",
  "description": "Source folder path"
}
```

#### 4. Multiple Input Files

When there are multiple inputs, use an array structure:

```json
"input_data": [
  {
    "type": "file",
    "name": "raster_file",
    "title": "Input Raster File",
    "description": "Input raster file path",
    "suffix_name": ["tif", "tiff", "img"],
    "required": true
  },
  {
    "type": "file",
    "name": "vector_file",
    "title": "Input Vector File",
    "description": "Input vector file path",
    "suffix_name": ["shp", "kml"],
    "required": true
  }
]
```

## Output Schema

```json
{
  "type": "object",
  "description": "Point cloud denoising result",
  "properties": {
    "count": {
      "type": "integer",
      "title": "Removed Point Count",
      "description": "Number of outliers removed"
    }
  },
  "required": ["count"],                  // Required return fields
  "output_data": { ... }                  // Actual output files
}
```

### Output File Specifications

#### 1. Single File Output

```json
{
  "type": "file",
  "name": "output_data",
  "title": "Output Point Cloud File",
  "description": "Output file path",
  "suffix_name": ["lidata"],
  "required": true
}
```

#### 2. Multiple File Output

```json
{
  "type": "multifile",
  "name": "result_files",
  "title": "Output Result File List",
  "description": "Result file list",
  "suffix_name": ["csv", "txt"]
}
```

#### 3. Directory Output

```json
{
  "type": "dir",
  "name": "output_dir",
  "title": "Output Directory",
  "description": "Output directory"
}
```

### output_data in input_schema

The `output_data` in `input_schema` is used to define the output path parameters that the user needs to **specify** (such as output directory or output file path), and is one of the tool's input parameters. The `output_data` in `output_schema` is used to define the tool's **actual output file declarations**.

These two can differ: for example, when clipping raster by polygon, `input_schema.output_data` is declared as a directory type (user specifies output directory), but `output_schema.output_data` should explicitly declare multiple (multifile) raster (tif) files.

If the output is a directory of tile data such as 3DTiles, both can use the directory type.

### Difference Between Output Directory and Output Files

Even if `output_data` in the input is declared as a directory type, the actual output may need to specify file types explicitly.

For example: when clipping raster by polygon, the input parameter is the **output directory** for result files, but the clipping result files are definitively multiple tif files. Therefore, in `output_schema`, you should explicitly declare the output as multiple (multifile) raster (tif) files.

If the output is a directory of tile data such as 3DTiles, you can use the directory type.

## Key Rules Summary

### 1. Naming Conventions

- **Interface name**: Lowercase snake_case (`pointcloud_outlier_removal`)
- **Parameter field names**: Lowercase snake_case (`layer_name`)
- **Allowed characters**: Only English letters (a-z, A-Z), digits (0-9), underscores (_); must start with an English letter
- **Disallowed characters**: No spaces, dots (.), commas (,), colons (:), Chinese characters, or any other special symbols
- **File name parameters**: Explicit suffix list (`["lidata"]`)
- **Uniqueness**: Interface names must be unique; no duplicates with other interfaces

### 2. Multi-Data Handling

- For multiple inputs/outputs, the key is still `input_data` / `output_data`, with the value as an array structure
- Each element in the array specifies one input/output structure, distinguished by the `name` field
- File types must be explicitly labeled as `file`/`multifile`/`dir`

### 3. Version Control

- The current wizard defaults to generating `1.0.0`; if the target runtime version has additional format constraints, refer to the wizard preview and actual loading verification results

### 4. Required Constraints

- Declare mandatory fields through the `required` array

## Complete Example

```json
{
  "interface": {
    "name": "pointcloud_outlier_removal",
    "title": "Point Cloud Denoising",
    "description": "Remove noise points while preserving point cloud geometric information to improve point cloud data quality",
    "version": "1.0.0",
    "category": "pointcloud_processing",
    "keywords": [
      "PointCloud",
      "PointCloud Outlier Removal",
      "removal noise"
    ]
  },
  "input_schema": {
    "type": "object",
    "description": "Point cloud denoising parameters",
    "properties": {
      "neighbor_points": {
        "type": "integer",
        "title": "Neighborhood Points",
        "description": "number of neighborhood points",
        "default": 10,
        "example": 10
      },
      "standard_deviation_multiples": {
        "type": "number",
        "title": "Standard Deviation Multiples",
        "description": "standard deviation multiples",
        "default": 5.0,
        "example": 5.0
      }
    },
    "required": [],
    "input_data": {
      "type": "file",
      "name": "input_data",
      "title": "Input Point Cloud File",
      "description": "point cloud file path",
      "suffix_name": ["lidata"],
      "required": true
    },
    "output_data": {
      "type": "file",
      "name": "output_data",
      "title": "Output Point Cloud File",
      "description": "Point cloud file path after outlier removal",
      "suffix_name": ["lidata"],
      "required": true
    }
  },
  "output_schema": {
    "type": "object",
    "description": "Point cloud denoising result",
    "properties": {
      "count": {
        "type": "integer",
        "title": "Removed Point Count",
        "description": "Number of outliers removed"
      }
    },
    "required": ["count"],
    "output_data": {
      "type": "file",
      "name": "output_data",
      "title": "Output Point Cloud File",
      "description": "Point cloud file path after outlier removal",
      "suffix_name": ["lidata"],
      "required": true
    }
  }
}
```
